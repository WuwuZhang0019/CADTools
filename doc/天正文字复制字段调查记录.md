# 天正文字复制字段调查记录

日期：2026-10-14

状态：读取字段已定位，天正写入接口待原生复测

## 样本来源与字段

依据用户在真实 CAD 中运行 `TZTXTDBG` 提供的五个样本日志。本表中的句柄只属于该张测试图，不作为程序常量。

| 样本 | 对象类型与句柄 | 已确认的文字位置 |
| --- | --- | --- |
| 1，上方引线标注 | `TCH_MULTILEADER`，`1CA8` | `TDbSymbMultiLeader` 子类内的组码 `1` 为“排烟风机”，组码 `2` 为“11kW，吊装”；两段均需保留 |
| 2，导线标注 `w1` | `TCH_WIREDIM2`，`1CAA` | 本体没有组码 `1`；XData `KeyOwnWireId` 的组码 `1005` 指向 `1CA9`。需继续读取关联导线，确认其 `linenum` 等字段 |
| 3，数字标注 `3` | `ATTRIB`，`1CAC` | 组码 `1` 为 `3`，标签组码 `2` 为 `N`；它是属性文字 |
| 4，天正单行文字 | `TCH_TEXT`，`1CAE` | `TDbText` 子类内的组码 `1` 为“天正单行文字输入” |
| 5，天正多行文字 | `TCH_MTEXT`，`1CAF` | `TDbText` 子类内的组码 `1` 包含两行内容，行间为 CRLF；本样本还有 `TDbMText` 子类 |

样本 2 的 XData 含 `TG_DIMWIRE_TYPE = WireNameOnly` 和 `KeyOwnWireId = 1CA9`。其他项目的一份真实图纸记录过 `TCH_WIREDIM2 -> KeyOwnWireId -> 导线 XData linenum` 的读取路径，但此处仍要核对本图 `1CA9` 的实际数据，不能直接把屏幕上的 `w1` 当作该字段已得到验证。

## 当前代码与下一步

旧版 `maa` 对第二次点选的对象直接调用 `entmod`。现已加类型保护：普通 `TEXT`、`MTEXT`、`ATTRIB` 仍可走已知写入路径；天正自定义目标在确认安全接口之前不会进入 `entmod`。`TCH_TEXT` 和 `TCH_MTEXT` 的组码 `1` 可作为复制来源。`TCH_WIREDIM2` 作为来源时只读尝试 `KeyOwnWireId -> 导线 linenum`，若本图缺少该字段则拒绝复制。`TCH_MULTILEADER` 有两段文字，暂不做有损复制。这些新路径仍待原生 CAD 验证。

增强后的 `TZTXTDBG` 会沿 XData 的 `1005` 句柄再读取一层，并只读查询对象公开 COM 文字属性的可用性和可写标志。请在测试图副本中重新探测样本 1、2、4、5，提交新日志。公开属性显示“可写”也不等于实际修改安全；正式接入还需在天正中验证写入、显示、保存重开和撤销，不对自定义对象盲用 `entmod`。

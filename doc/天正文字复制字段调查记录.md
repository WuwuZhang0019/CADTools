# 天正文字复制字段调查记录

日期：2026-10-14

状态：五类样本读取字段已定位，目标写入条件待原生复测

## 样本来源与字段

依据用户在真实 CAD 中运行 `TZTXTDBG` 提供的五个样本日志。本表中的句柄只属于该张测试图，不作为程序常量。

| 样本 | 对象类型与句柄 | 已确认的文字位置 |
| --- | --- | --- |
| 1，上方引线标注 | `TCH_MULTILEADER`，`1CA8` | `TDbSymbMultiLeader` 子类内的组码 `1` 为“排烟风机”，组码 `2` 为“11kW，吊装”；两段均需保留 |
| 2，导线标注 `wl1` | `TCH_WIREDIM2`，`1CAA` | 本体没有组码 `1`；XData `KeyOwnWireId` 的组码 `1005` 指向 `1CA9`；该 `LWPOLYLINE` 的 XData `linenum` 组码 `1000` 为 `wl1` |
| 3，数字标注 `3` | `ATTRIB`，`1CAC` | 组码 `1` 为 `3`，标签组码 `2` 为 `N`；它是属性文字 |
| 4，天正单行文字 | `TCH_TEXT`，`1CAE` | `TDbText` 子类内的组码 `1` 为“天正单行文字输入” |
| 5，天正多行文字 | `TCH_MTEXT`，`1CAF` | `TDbText` 子类内的组码 `1` 包含两行内容，行间为 CRLF；本样本还有 `TDbMText` 子类 |

第二份日志 `TZTXTDBG (1).txt` 已在本图确认 `TCH_WIREDIM2 -> KeyOwnWireId -> 导线 XData linenum` 的读取链。其 `TG_DIMWIRE_TYPE` 为 `WireNameOnly`，关联导线句柄为 `1CA9`。截图中容易把小写字母 `l` 看成数字 `1`；日志里的原值是 `wl1`。

COM 只读探测显示：`TCH_TEXT` (`TDbText`) 的 `Text` 属性可读、可写；`TCH_MULTILEADER`、`TCH_WIREDIM2`、`TCH_MTEXT` 在已探测的 `TextString`、`Text`、`Content`、`Contents`、`Text1`、`Text2`、`LineNum`、`WireName` 属性中都没有可用项。探测到 setter 仅说明接口存在，尚不能证明写入后能正确显示、保存重开及撤销。

## 当前代码与下一步

旧版 `maa` 对第二次点选的对象直接调用 `entmod`。现已加类型保护：普通 `TEXT`、`MTEXT`、`ATTRIB` 走原有写入路径；天正自定义目标不会进入 `entmod`。五类样本均可作为复制来源：引线标注的组码 `1`、`2` 合成两行；导线标注只读关联导线的 `linenum`；属性文字、天正单行和多行文字读取组码 `1`。写入普通 `MTEXT` 时将 CRLF 转为 `\P`。`TCH_TEXT` 目标通过探测到的 COM `Text` 属性写入，并校验 COM 与 DXF 组码 `1` 的读回；校验不一致时尝试恢复原值。

本次升级后，`TCH_MULTILEADER` 目标会在运行时核对 `UpText`、`DownText` 是否都可写、当前值是否分别等于 DXF 组码 `1`、`2`；符合条件时才写入最多两行文字，随后读回两处 COM 属性和两个 DXF 字段。`TCH_MTEXT` 目标会在候选公开属性中寻找可写且当前值与组码 `1` 相同的属性，找到后才写入、读回和校验。写入失败会尝试恢复原值。上述属性在用户提供的日志中尚未确认，不能将“有条件路径”当作已经通过原生测试。`TCH_WIREDIM2` 目标仍拒绝写入，因为关联导线上的 `linenum` 可能被其他标注共享。

增强后的 `TZTXTDBG` 会沿 XData 的 `1005` 句柄再读取一层，并只读查询更多候选 COM 属性（包括 `UpText`、`DownText`、`MText`、`TextContent`、`MTextContent`）及其值。下一轮在测试图副本中分别把样本 1、4、5 选为目标运行 `maa`，记录命令行提示、画面、保存重开和撤销结果。若样本 1 或 5 提示接口不可用，再用 `TZTXTDBG` 探测该样本并提交日志。其他天正目标的安全写入接口未确认前不盲用 `entmod`。

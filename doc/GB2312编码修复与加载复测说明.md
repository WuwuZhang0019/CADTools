# CADTools LSP 编码与加载复测说明

日期：2026-10-14

状态：仓库 LSP 编码已调整，目标 AutoCAD 加载待复测

## 适用范围

本项目的 `.lsp` 文件直接以 **GB2312、无 BOM** 保存，包括 `Zyf.autoCAD/Tools/` 中由菜单命令加载的脚本、独立调查脚本，以及 `test/` 中的 LSP 样本。Markdown、C#、Python、项目配置等其他文本文件仍使用 UTF-8。`.VLX` 和可执行文件是二进制文件，不做文本转码。

这里的要求针对仓库里的 LSP 文件本身；不要再把 UTF-8 的 `.lsp` 源文件直接交给旧版 CAD 加载，也不要把现有 GB2312 文件按 UTF-8 误读后覆盖。

## 本项目的加载与构建路径

- `Zyf.autoCAD/MyCommand.cs` 中的菜单命令从插件 `Contents/Tools/` 加载对应 `.lsp`。第 13 项 `YJST` 使用程序集所在目录拼接 `Tools/13 一键统一宋体(yjst).lsp`。
- `Zyf.autoCAD/ZYF.autoCAD.csproj` 将这些 LSP 文件复制到输出目录。源文件现已是 GB2312，构建时按原始字节复制；原先只针对第 13 项的 UTF-8 转 GB2312 后处理已移除。
- `Zyf.autoCAD/Tools/06 文字复制-天正对象探测.lsp` 是独立诊断脚本，需在 CAD 中用 `APPLOAD` 手动加载，目前不属于安装包菜单项。脚本及中文操作提示直接以 GB2312 保存。

本次将原来使用 UTF-8 的 `02 布置地面疏散指示(mee).lsp`、`03 底图处理(DTCL).lsp`、`05 图片去黑框(QHK).lsp`、`13 一键统一宋体(yjst).lsp` 严格转为 GB2312，保持解码后的文本内容一致。其他已符合 GB2312 的 LSP 没有批量重写。

## 修改 LSP 时的检查

1. 编辑器对 `.lsp` 明确选择 GB2312 保存，不能依赖笼统的“ANSI”显示。不可编码字符应明确报错，逐处改成 GB2312 可表示且语义相同的文字；禁止忽略、替换或用问号吞掉字符。
2. 在仓库根目录运行：

   ```powershell
   python -X utf8 tools/check_gb2312_lsp.py
   ```

   检查器递归覆盖 `Zyf.autoCAD/Tools/` 和 `test/` 下的 `.lsp`，要求严格 GB2312 解码、编码后字节完全一致且无 BOM。ASCII 文件自然通过。
3. 若修改了插件菜单加载的脚本，构建后核对输出目录对应文件与源码的字节或 SHA-256 一致。不要从旧安装目录或旧 `bin` 目录复测。
4. 编码检查只证明文件字节符合要求，不证明 AutoLISP 语法、命令行为或天正对象兼容。

## 目标 CAD 加载复测

在新的 AutoCAD 会话中，记录 CAD 版本、实际加载路径、文件 SHA-256、命令行输出和出错阶段。通过菜单或 `APPLOAD` 加载本次文件，再执行对应命令，检查中文提示、运行结果及必要的保存重开。若加载后仍有 `stringp nil`、语法错误或其他异常，先核对加载文件身份，再按实际错误调用路径排查；不要把错误一律归因于编码。

对文字复制的天正支持，应先运行 `TZTXTDBG`，分别点选三种标注文字、天正单行文字和多行文字，保存日志后确认其真实 DXF/XData 字段，再修改 `maa`。探测脚本通过静态编码检查不代表 `maa` 已支持天正，也不代表原生 CAD 复测完成。
